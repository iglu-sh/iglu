# IGLU-2026-004: Deduplication allows any tenant to overwrite any other tenant's files 

> **Summary:** Uploading a derivation to an Iglu tenant may overwrite that same file for other tenants if that same nix derivation path is present in the victim tenant, allowing a hacker to potentially serve malware

## Impact

An attacker may be able to upload malware on any tenant by uploading an already cached derivation on the Iglu-Cache Server due to a flaw in Iglu's deduplication logic.

## Affected configurations

All configurations affected

## Remediation

**Upgrade** to a fixed version by updating the Iglu Docker or Nix Service:

### Docker Compose:

```diff
services:
    postgres:
        image: "postgres:18.3"
        environment:
            POSTGRES_PASSWORD: "changeme"
            POSTGRES_DB: "iglu"
    iglu:
-        image: "ghcr.io/iglu-sh/iglu-cache:v0.0.2"
+        image: "ghcr.io/iglu-sh/iglu-cache:v0.0.3"
        volumes:
            - "./binaries:/binaries"
            - "./config:/config"
        environment:
            IGLU_CACHE_CONF: "/config/config.toml" # Sets which directory should be searched for your config.toml
        depends_on:
            - "postgres"
        ports:
            - "80:80"
```

### Nix Service:
Run `nix flake update` and re-start the Iglu service.

## Technical details

The root cause of this issue was a flaw in the deduplication logic of iglu which didn't check for either if the file hash of the uploaded file 
matches the potentially already stored file hash or if that file already existed in the target filesystem backend, 
causing the file to be overwritten by iglu with potentially malicous files
